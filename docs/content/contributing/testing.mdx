`e2e` is a Payload site on Cloudflare Workers that exists to be tested. It installs Offload from a registry the way a real site does, and Playwright drives its Worker build in local workerd. The suite tests what Offload changes or depends on, plus the main editor flows. Payload's own test suite covers Payload's features.

## Run the suite

```bash
pnpm release e2e
pnpm release e2e --postgres
```

The Postgres run needs Docker. CI runs both on every pull request and every push to `main`. Each run does these steps:

1. Start a registry that exists only for the run, and publish the working tree to it.
2. Install `e2e` from that registry. Every run publishes the same version, so the install starts from an empty `node_modules`.
3. Type-check `e2e`.
4. Reset the local D1 and R2 state, or the Postgres schema. Apply the migrations, create a page, drop the database with `migrate:fresh`, roll back every migration with `migrate:down`, and apply them again. Then build the Worker.
5. Serve the build with `vite preview`, create the first admin user through the admin panel, and run the suite.

## Rerun the suite without publishing

After one `pnpm release e2e`, `e2e` has the release installed. From `e2e`, run `pnpm test`, or `CLOUDFLARE_ENV=postgres pnpm test` for Postgres.

To read the Worker's logs, start the server yourself:

```bash
node scripts/prepare.ts && pnpm preview
```

Then run the suite from another terminal. It uses the running server:

```bash
E2E_REUSE_SERVER=1 pnpm exec playwright test
```

## What the suite covers

| File                     | Covers                                                                                                                                                                                                                                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/auth.setup.ts`    | Creating the first user through the admin, which hashes the password inside the Worker                                                                                                                                                                                                                        |
| `tests/admin.spec.ts`    | Admin rendering, server functions, and saves: drafting, publishing, and translating a page, uploading to R2, and a document with every field type                                                                                                                                                             |
| `tests/api.spec.ts`      | REST, GraphQL queries with arguments, and access control                                                                                                                                                                                                                                                      |
| `tests/database.spec.ts` | A duplicate value in a unique field, which must be the same validation error on D1 and Postgres                                                                                                                                                                                                               |
| `tests/workers.spec.ts`  | R2 byte ranges, image variants through the Images binding, updating and deleting an image whose seven variants pass D1's parameter limit, a password reset email through Email Service, hooks and endpoints in the Worker, Cron-driven jobs and scheduled publishing, and the search and form-builder plugins |
| `tests/frontend.spec.ts` | TanStack Start routes that render Payload content through the Local API, with a post's rich text returned from a server function as a React Server Component                                                                                                                                                  |
| `tests/sessions.spec.ts` | Concurrent logins as one user, which each keep a session that authenticates, and a logout that ends only its own session                                                                                                                                                                                      |

## How the site is set up

| File                                           | Purpose                                                                                                                                   |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `wrangler.jsonc`                               | D1, R2, Images, and Email Service by default. The `postgres` environment binds Hyperdrive to the Docker Postgres in `docker-compose.yml`. |
| `src/payload.config.ts`                        | Picks the database adapter from the binding that exists                                                                                   |
| `src/migrations/d1`, `src/migrations/postgres` | One migration history per database. After a schema change, run `pnpm payload migrate:create`, then again with `CLOUDFLARE_ENV=postgres`.  |
| `src/jobs.ts`                                  | A job task, a workflow, and two endpoints that queue work for the Cron Trigger                                                            |
| `src/collections/FieldTypes.ts`                | Every field type that works on both SQLite and Postgres                                                                                   |

The `/api/e2e/*` endpoints exist only for the suite. Payload closes its jobs collection to REST, and a real site should keep it closed.

## Test on Cloudflare

Some behaviour shows up only on a deployed Worker, such as the Workers limit on password hashing that the [PBKDF2 patch](/patches/workers-pbkdf2-cap) works around. The `staging` environment in `wrangler.jsonc` deploys `e2e` as `offload-e2e-staging`, with its own D1 database and R2 bucket. From `e2e`, run:

```bash
pnpm deploy:staging
```

The command applies migrations to the remote D1 database, builds for staging, and deploys. The staging admin's credentials are in `e2e/.staging-admin.json`, which git ignores. `PAYLOAD_SECRET` is a Wrangler secret on the Worker.
