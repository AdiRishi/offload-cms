title: Develop Offload
description: Set up the repository, find your way around it, and run the commands that build, test, and release Offload.

You need Node 24 and pnpm through Corepack. Docker is needed only for the Postgres test run.

```bash
pnpm install
pnpm upstream checkout
pnpm check
```

`pnpm upstream checkout` clones Payload at the pinned commit into `upstream/payload` and applies the patches. `pnpm check` runs the linter, the format check, the type checks, and the tests. It builds Payload first, because the packages in `packages/` type-check against the patched build: that build writes `upstream/tsconfig.payload.json`, which maps each Payload entry point to its built declarations, and `@repo/tsconfig/library.json` extends it. Turborepo's cache inside `upstream/payload` makes later builds take seconds.

`pnpm check` skips `e2e`, whose dependencies exist only after `pnpm release e2e` installs them from its registry. `pnpm release e2e` lints and type-checks `e2e` after that install.

## Layout

<FileTree>

- packages/
  - accounts/ `@adirishi/offload-accounts`, published, and the shadcn registry in `registry.json`
  - cloudflare/ `@adirishi/offload-cloudflare`, published
  - email-cloudflare/ `@adirishi/offload-email-cloudflare`, published
  - form-builder/ `@adirishi/offload-form-builder`, published, and the shadcn registry in `registry.json`
  - payments/ `@adirishi/offload-payments`, published, and its registry items in `registry.json`
  - tanstack/ `@adirishi/offload-tanstack`, published
  - tsconfig/ `@repo/tsconfig`, the TypeScript configs that every package extends
- upstream/ `@repo/upstream`
  - payload.json the pinned Payload release
  - patches/ one `git format-patch` file per change to Payload
  - payload/ the Payload checkout, created by `pnpm upstream checkout`
  - src/ the `upstream` CLI
- release/ `@repo/release`, the `release` CLI
- e2e/ a Payload site on Workers that the Playwright suite drives
- docs/ this site

</FileTree>

The pnpm workspace holds `docs`, `packages/*`, `upstream`, and `release`. Every dependency version comes from the catalog in `pnpm-workspace.yaml`. Node runs the `upstream` and `release` CLIs straight from TypeScript. `e2e` is a separate pnpm project, because it installs Offload from a registry the way a site does.

The docs build runs `docs/registry.ts`, which runs `shadcn build` on the `registry.json` of each package in `packages/` that has one, and serves the registry items from `/r/` on this site. It stamps each item's `meta` with its package and the release that the docs show, so a site can match the items to its package version. `pnpm --filter @repo/docs registry` builds them alone.

## Commands

`pnpm format:fix` and `pnpm lint:fix` fix most of what `pnpm check` reports, and `pnpm docs:dev` serves this site. Run `pnpm upstream` or `pnpm release` with no command to print its commands.

## Editor

Install the recommended oxc extension. `.vscode/settings.json` formats on save, applies lint fixes, and turns on type-aware lint rules.
