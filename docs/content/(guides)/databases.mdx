---
title: Choose a database
description: Pick D1 or Postgres through Hyperdrive for an Offload site, and configure the one you pick.
---

Use D1 for content sites that a few people edit. Use Postgres through Hyperdrive when a half-written document is unacceptable, such as on a site that takes payments. The e2e suite runs on both on every push.

## What D1 gives up

D1 has no transactions that a Worker can open and commit, so every statement commits on its own. Payload saves one document as several statements: the main row, rows for arrays and blocks, relationship rows, and a version row.

Validation and `beforeChange` hooks run before the first write, so the usual failures leave the database untouched. A Worker that stops partway through a save can leave a document half-written. Keep versions enabled on collections that matter, so you can restore the last good version. An `afterChange` hook that throws doesn't undo the save.

Postgres has real transactions, at the cost of a database outside Cloudflare.

## Use D1

Bind the database in `wrangler.jsonc` and pass the binding to the adapter:

```ts src/payload.config.ts
import { getBindings } from "@adirishi/offload-cloudflare";
import { sqliteD1Adapter } from "@payloadcms/db-d1-sqlite";

const env = await getBindings();

const db = sqliteD1Adapter({
  binding: env.D1,
  migrationDir: path.resolve(dirname, "migrations"),
  push: false,
});
```

## Use Postgres through Hyperdrive

<Steps>
  <Step title="Install the adapter">
    ```json package.json
    "@payloadcms/db-postgres": "npm:@adirishi/offload-db-postgres@{{version}}",
    "pg": "^8.20.0"
    ```
  </Step>
  <Step title="Bind Hyperdrive">
    Create a Hyperdrive configuration for your database with `pnpm wrangler hyperdrive create`, then bind it. `localConnectionString` is the database that `vite dev`, `vite preview`, and the Payload CLI use on your machine.

    ```jsonc wrangler.jsonc
    "hyperdrive": [
      {
        "binding": "HYPERDRIVE",
        "id": "<the ID from hyperdrive create>",
        "localConnectionString": "postgres://user:password@localhost:5432/my-site"
      }
    ]
    ```

  </Step>
  <Step title="Configure the adapter">
    ```ts src/payload.config.ts
    import { getBindings, hyperdrivePoolConfig } from "@adirishi/offload-cloudflare";
    import { postgresAdapter } from "@payloadcms/db-postgres";

    const env = await getBindings();

    const db = postgresAdapter({
      migrationDir: path.resolve(dirname, "migrations"),
      pool: hyperdrivePoolConfig(env.HYPERDRIVE),
      push: false,
    });
    ```

    A Worker can read `env.HYPERDRIVE.connectionString` only inside a request. `hyperdrivePoolConfig()` reads it when Payload opens its pool, during the first request. It also gives each query a new connection, because Hyperdrive does the pooling.

  </Step>
</Steps>

## Migrations

Set `push: false` on either adapter, so migrations own the schema and a local database can't drift from production. After you change a collection, generate a migration and apply it:

```bash
pnpm payload migrate:create
pnpm payload migrate
```

D1 and Postgres generate different SQL. A site that runs on both, as `e2e` does, keeps a migration directory for each.
