The main entry point runs in the browser and on the server. `@adirishi/offload-form-builder/server` imports Payload and the Turnstile check, and runs only on the server.

The form's UI isn't in the package. The [registry](#registry) installs it into the site. [Take form submissions](/forms) sets up both.

## Supported fields

The package handles the blocks that the form builder plugin enables by default: `checkbox`, `country`, `email`, `message`, `number`, `select`, `state`, `text`, and `textarea`. `isInputField()` leaves out every other block, such as `radio`, `date`, `payment`, or `upload`, so a form with one still validates and saves its other fields. The registry components give a type error when the site's generated `Form` type has such a block.

Validation messages are in English and can't be changed.

## formSchema()

The browser validates with this schema as the visitor types, and `saveFormSubmission()` validates again against the stored form, so the two always apply the same rules:

| Block      | Rule                                        | Message when the rule fails       |
| ---------- | ------------------------------------------- | --------------------------------- |
| `checkbox` | If `required`, must be `true`               | This field is required.           |
| `country`  | The `value` of one of `countries`           | Choose a country from the list.   |
| `email`    | An email address of at most 254 characters  | Enter a valid email address.      |
| `number`   | Digits, with an optional minus and decimals | Enter a number.                   |
| `select`   | One of the field's option values            | Choose one of the options.        |
| `state`    | At most 100 characters                      | Keep this under 100 characters.   |
| `text`     | At most 500 characters                      | Keep this under 500 characters.   |
| `textarea` | At most 5,000 characters                    | Keep this under 5,000 characters. |

The schema trims string values. A required field fails on an empty or missing value with "This field is required." An optional field accepts an empty value, or no key at all, so a component can send only some of a form's fields.

## defaultValues()

A checkbox without a default starts as `false`. A number's default becomes a string, because a number field's value is the text the visitor typed.

## submissionData()

The admin and the form builder's emails show each row's value as it is, so the rows are for people to read. A country answers with its name and its ISO 3166-1 alpha-2 code, such as `"Mauritius (MU)"`. The name makes an email readable, and the code identifies the country after its English name changes. Payload's website template submits the code too, but saves it alone.

## isInputField()

It narrows the site's generated field type, so filter `form.fields` with it before the fields reach `formSchema()`.

## submissionInput

To send more, such as the page that a form is on, extend it, such as `submissionInput.extend({ page: z.number() })`, and save the extra value through the `data` option of `saveFormSubmission()`.

## saveFormSubmission()

It runs these checks in order and returns at the first one that fails:

1. The rate limit, keyed by the `cf-connecting-ip` header as `form:<ip>`. Over the limit, it returns `limited`. `vite dev` doesn't set the header, so every request in dev shares one allowance.
2. The Turnstile token, through [`verifyTurnstile()`](/cloudflare#verifyturnstile) with the request's hostname and the action `form`. A token that fails returns `unverified`.
3. The form. A visitor must be able to read it, through a query with `overrideAccess: false`, and `isOffered` must accept the stored document. Otherwise it returns `refused`.
4. The answers, validated with `formSchema()` against the stored form. Invalid answers return `invalid`, with the first message for each field in `errors`.

Then it creates the submission in `form-submissions` with `overrideAccess: true` and returns `sent`. Because the save bypasses access control, `form-submissions` can stay closed to public creates. The form builder plugin allows public creates by default, and [Take form submissions](/forms) closes them. The submission's `form` and `submissionData` replace the same keys in `data`. If anything throws, it logs the error and returns `error`, so the visitor never sees the cause.

`isOffered` is required because the form builder lets anyone read every form, including drafts, tests, and forms that no page shows any more. Without it, a visitor could submit to any of them. [Choose which forms take submissions](/forms#choose-which-forms-take-submissions) shows a rule.

## Registry

Offload's shadcn registry installs the form's UI as source files that the site owns and edits. The docs build publishes each item at `https://adirishi.github.io/offload-cms/r/<item>.json`, from [`packages/form-builder/registry.json`](https://github.com/AdiRishi/offload-cms/blob/main/packages/form-builder/registry.json).

| Item                | Installs                                                                                     | shadcn components the site adds                               |
| ------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `turnstile`         | `components/form-builder/turnstile.tsx`                                                      | None                                                          |
| `form-fields`       | `components/form-fields.tsx`                                                                 | `button`, `checkbox`, `field`, `input`, `spinner`, `textarea` |
| `form-builder-form` | `components/form-builder/form.tsx` and `form-client.tsx`, with `form-fields` and `turnstile` | Those of `form-fields`                                        |
| `newsletter-signup` | `components/form-builder/newsletter-signup.tsx`, with `turnstile`                            | `button`, `field`, `input-group`, `spinner`                   |

Registry dependencies name only other `@offload` items. `shadcn add --overwrite` rewrites every file of every registry dependency, so an item that listed `button` would replace the site's own button on every update. Add the shadcn components that an item imports to the site yourself, with `pnpm dlx shadcn@latest add`.

The [account forms](/accounts#registry) build on `form-fields` too.

Each item targets one release of `@adirishi/offload-form-builder`, and its `meta` names it, such as `"meta": { "@adirishi/offload-form-builder": "{{version}}" }`. The registry serves only the items for the latest release. Update the package and add the items again together.

`turnstile` also adds `VITE_TURNSTILE_SITE_KEY` with Cloudflare's testing site key to `.env.local`. The registry doesn't list `@adirishi/offload-form-builder`, so the shadcn CLI never changes its version.

The components import `submitForm` from `@/server/forms.functions`, which the site writes and imports once in its `_frontend` layout route. Only server components render the forms, and TanStack Start's production build doesn't register a server function that it reaches only through server components. Without the layout import, every submission on a production build fails, as [Take form submissions](/forms) explains.

The components use only the shadcn components whose props Radix and Base UI share, so they install into a project on either library. Select and country fields render a native `<select>`, styled in `form-fields.tsx`.

### FormBuilderForm

A server component from `components/form-builder/form.tsx`. It takes a populated form document. It renders the rich text of `message` blocks and of the confirmation message on the server, and passes React nodes to the client form in `form-client.tsx`.

After a successful submission, the client form shows the confirmation message, or goes to the form's redirect URL. A URL that starts with `/` navigates on the client, and any other URL loads as a new page.

### NewsletterSignup

A client component from `components/form-builder/newsletter-signup.tsx`. It renders one email input and submits it as the form's first `email` field. It always validates the address as a required email, whatever the field's own `required` setting, and sends no other field, so the form's other fields must be optional. A form without an `email` field fails every sign-up with the generic error.

### Turnstile

Both forms render the Turnstile widget with the action `form` when the visitor first focuses or touches the form, and ask it for a token on submit. `saveFormSubmission()` rejects a token for any other action, so keep `action="form"` when you edit the components. The widget takes space only when the visitor has to interact with it. The site key's settings in Cloudflare choose the widget mode.
